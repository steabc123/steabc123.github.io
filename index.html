解决每次github部署完成后都要重新绑定域名的问题

前言

在使用 Hexo 搭建博客并部署到 GitHub Pages 时，很多人会遇到一个问题：每次执行 hexo deploy 部署后，GitHub Pages 的自定义域名设置就会被清除，需要重新在 GitHub 仓库设置中绑定域名。

这个问题非常烦人，但其实有一个简单的解决方案。

问题原因

Hexo 在部署时会将 `public` 目录下的所有文件推送到 GitHub 仓库。如果在 `source` 目录下没有 `CNAME` 文件，或者该文件被 Hexo 渲染处理了，那么部署到 GitHub 后就会丢失域名配置信息。

解决方法

步骤一：配置 skip_render

在博客根目录的配置文件 _config.yml 中找到 skip_render 字段，添加 CNAME，用来指定不进行渲染的文件。

如果 skip_render 字段不存在，可以手动添加。

步骤二：创建 CNAME 文件

在 /source 目录中创建一个文件，文件名为 CNAME（注意没有扩展名）。

步骤三：填写域名

在 CNAME 文件中写入你的域名，只写域名，不需要添加 http:// 或 https:// 前缀。

验证配置

完成以上配置后：

  1. 执行 hexo clean 清理缓存
  2. 执行 hexo generate 生成静态文件
  3. 执行 hexo deploy 部署到 GitHub
  4. 检查 GitHub 仓库中是否包含 CNAME 文件
  5. 访问你的自定义域名，确认网站正常访问

注意事项

  • CNAME 文件名必须是大写，且没有文件扩展名
  • 文件中只能包含域名，不要有空格或其他字符
  • 如果使用多个域名，每行写一个域名（但通常只需要一个）
  • 确保你的域名 DNS 解析已正确配置指向 GitHub Pages

总结

通过在 source 目录添加 CNAME 文件并配置 skip_render，就可以永久解决每次部署后需要重新绑定域名的问题。这个配置会让 Hexo 在每次部署时都将 CNAME 文件一起推送到 GitHub，GitHub Pages 会自动识别并应用域名配置。

全局安装意味着什么？

全局安装的包会被放置在系统级别的一个公共目录中，而不是某个特定项目的文件夹里。

这样做的好处是，安装完成后，你就可以在命令行中的任何位置直接使用 hexo 命令来创建和管理博客，而无需在每个项目中都单独安装一次。

💡 温馨提示
如果你在安装后遇到 hexo: command not found 或类似错误,这通常是因为系统的环境变量(PATH)没有配置好,导致系统找不到全局安装的命令。
你可以检查一下 Node.js 和 npm 的环境变量设置是否正确。

2. 次要问题：目录非空
如果你在解决了 Node.js 版本问题后，再次运行命令遇到此报错。
错误信息： FATAL G:\myblog not empty, please run \hexo init on an empty folder`
原因分析： Hexo 要求初始化的文件夹必须是空文件夹。你当前的 G:\myblog 文件夹中可能已经存在文件（比如你之前尝试初始化留下的 .git 文件夹，或者是 package.json 等）。
解决方案：
方案 A（推荐）： 删除 G:\myblog 文件夹下的所有内容（或者直接删除该文件夹），然后重新运行 hexo init。
方案 B： 换一个全新的空文件夹路径运行命令，例如 G:\hexo_blog。

总结: 你的主要阻碍是 Node.js 版本太低。Hexo 的新版本对环境要求更严格了,请务必先升级 Node.js 到 20.19.0 以上,然后再处理文件夹是否为空的问题。
